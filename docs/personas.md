# Personas — the compiled voice layer

A persona shapes what a session notices and how it reports. It never adds
authority, relaxes a safety rule, changes a required action, or replaces an
output format. Those live in each target's `CLAUDE.md` and in its skill, and
they win every time. `bin/persona-compile` resolves the source layers into one
body per role and installs it.

## The layers

```
personas/
  WORLDVIEW.md          shared beliefs — every role gets this
  HOUSE_STYLE.md        prose rules — every role gets this
  roles/<role>.md       what THIS role notices and how it reports
  crews/<crew>.md       the costume: register and tone
  config.toml           installation policy (gitignored)
  config.example.toml   the committed documented form
  compiled/<role>.md    generated; the artifact `--check` compares against
  compiled/MANIFEST.md  generated; the audit record
```

`config.toml` picks a crew per tier (`hub`, `loop_crew`) and maps each role to
a target file under `[targets]`. `roles/*` and `config.toml` are gitignored,
because which roles an estate has and which sessions wear them is installation
policy — the same treatment `loops.toml` gets. `roles/example.md` is committed
as a template to copy.

## Why the body is a sidecar, and why the import must be a sibling

`--install` does **not** write the compiled body into the target. It writes the
body to a `persona.md` beside the target and puts a stable `@persona.md` import
between the target's generated markers. Two properties follow, and both are the
reason the design is shaped this way.

**The target stays byte-stable.** The installed block carries only `role` — no
crew, no content hash, nothing derived from the persona's text. So a persona
edit changes the sidecar and leaves the operational-contract file untouched. It
also means an up-to-date pointer proves nothing about the body behind it, which
is why `--check` compares the sidecar on its own.

**The import has to be a sibling.** The harness resolves `@` when it injects
`CLAUDE.md`, so the body is in the prompt at startup and after auto-compaction.
Several forms that look equivalent are not:

| Form | Result |
|---|---|
| body inlined in the target | works, but rewrites the target on every recompile |
| `Persona: load ./personas/compiled/<role>.md` | **loads nothing** — depends on the model choosing to `Read` |
| `@persona.md` (a sibling) | works, even with file-reading tools denied |
| `@../../personas/compiled/<role>.md` | **loads nothing**, silently |
| `@/absolute/path` | **loads nothing**, silently |

A non-sibling import fails with no error at all, leaving a session wearing no
persona. That is why the body is copied beside each target rather than imported
from `personas/compiled/`.

### How to re-run that check

The failure mode is silent, so the probe has to make the persona the *only*
possible source of the answer:

1. Pick a target that has a compiled persona installed (`--install` first).
2. Start a headless session in that target's directory on a small model, with
   the file-reading tools denied — `--disallowedTools Read Glob Grep` — so
   nothing can arrive via a tool call.
3. Ask it something only the persona body says, e.g. what role it is and what
   its signature is.
4. Repeat with the import rewritten by hand to `@../../personas/compiled/<role>.md`
   and to an absolute path.

The sibling form answers. The other two answer as though no persona exists, and
emit no error anywhere.

`tests/test_persona_compile.py::TestInstall::test_the_import_is_a_bare_sibling_never_a_path`
guards the compiler side of this — it fails if the installed import ever stops
being a bare sibling. Nothing can guard the harness side automatically: see
"What `--check` does not prove" below.

### It works through the AGENTS.md / CLAUDE.md symlink

This repo keeps `AGENTS.md` as the real file with `CLAUDE.md` symlinked to it.
Point `[targets]` at the canonical file (`AGENTS.md`). Naming the symlink also
works — the write follows it through and the link survives — but the canonical
path is what you mean. Either spelling puts the sidecar in the same directory,
so the import still resolves.

## What `--check` does not prove

`--check` compares generated bytes against generated bytes: each
`compiled/<role>.md` against what the compiler would render now, each installed
block against `block(rec)`, each sidecar against `sidecar(rec)`. Every comparand
comes from the in-memory record. A clean report therefore means *the compiler
agrees with itself and with its sources* — it does not mean any session actually
loaded a persona.

It does catch the failures that leave a trace on disk: a stale or missing
sidecar, a stale installed block, a target with no markers or malformed ones, a
compiled file that no longer matches its sources, an orphaned block whose role
is no longer in `[targets]`, and an orphaned file in `compiled/`.

What it cannot catch is the assumption above being wrong. If a sibling `@`
import ever stops resolving, every file still matches, `--check` still prints
`check: clean`, and every session runs bare. Re-run the probe in this document
after a harness upgrade; that is the only detector.

## Everyday use

```bash
cp personas/config.example.toml personas/config.toml   # once
bin/persona-compile                                     # compile to personas/compiled/
bin/persona-compile --install                           # wire the targets
bin/persona-compile --check                             # exit 1 on drift
bin/persona-compile --print <role>                      # body to stdout
python3 tests/test_persona_compile.py                   # the suite
```

Adding a persona to a loop takes three things, and the compiler will not invent
any of them:

1. `personas/roles/<role>.md` — copy `roles/example.md`.
2. The role named under `[targets]` in `personas/config.toml`, pointing at the
   target file.
3. The marker pair already present in that target file, where you want the
   import to sit:

   ```markdown
   <!-- BEGIN GENERATED PERSONA — bin/persona-compile · role=<role> -->
   <!-- END GENERATED PERSONA -->
   ```

Then `bin/persona-compile --install`. A target with no markers is reported as
drift and left untouched — placement is a decision the compiler never makes for
you.

Applying a recompiled persona to a *running* loop is a deliberate restart, done
by hand. Nothing here starts, stops, or talks to a session.
